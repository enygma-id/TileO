# Official implementation import and provenance protocol

The repository's first commit establishes publicly visible identity and governance. Application code can be introduced in a later, reviewable PR **only by accounts explicitly granted GitHub access**.

## Before code submission

1. Confirm copyright ownership or sufficient publication and commercial relicense rights for every submitted component.
2. Record the source snapshot, author(s), transfer history, and any pre-existing proprietary/institutional constraints.
3. Obtain applicable CLA signatures or corporate contribution authorization **before merge**; do not presume a CLA is executed merely because its text is in this repository.
4. Inspect generated files, binaries, credentials, datasets and sample content for redistribution rights.
5. Build a third-party manifest including direct/transitive packages and external executable binaries/drivers, with attribution and license texts.
6. Review tests, security exposures, documented limits and unverifiable marketing claims.

## PR requirements

- Source branch and clean signed/attributed commit history where possible.
- Complete implementation, tests and fixtures permitted for publication.
- Documentation consistent with code and meaningful reproducible smoke tests.
- Rechecked relative links, workflow paths, LICENSE/NOTICE headers, dependencies, file-size exclusions and credentials.
- Approval by designated core maintainer and steward for any license-rights exception.
